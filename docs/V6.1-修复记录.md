# xifeng 阅读 · V6.1 修复记录：PDF 导入失败 + 扫描版位图显示

> 背景：V6.1 交付扫描版 PDF 按页位图阅读后，浏览器实测发现导入、显示与缩放仍有问题。
> 本文记录三次修复的根因、方案与验证，作为 [V6.0-PDF支持方案.md](V6.0-PDF支持方案.md) 的补充。

## 修复一：PDF 导入失败（三连缺陷叠加）

**现象**：导入 PDF 报「扫描版第 1 页渲染失败：TypeError — Cannot read properties of null
(reading 'sendWithPromise')」，或导入成功后打开显示空白、点按/进度条不翻页。

### 根因 1：扫描版回退前误销毁 loadingTask（src/core/importers/pdf.ts）

文字抽取通道结束时立即 `task.destroy()`，但扫描版回退还要用**同一个 doc** 逐页渲染位图。
提前销毁拆掉 pdf.js 的 WorkerTransport，后续 `doc.getPage()` 抛
`Cannot read properties of null (reading 'sendWithPromise')`，导入直接失败。

**修复**：销毁统一推迟到扫描渲染通道结束（全文件唯一的常规销毁点）；
两个非正常出口单独销毁——Node 无 canvas 的提前抛错前、非扫描版但正文为空的出口。
扫描版元信息（Title/Author）改在 destroy 之前取，否则静默丢失。

### 根因 2：滚动模式渲染分支缺扫描版处理（src/pages/ReaderPage.tsx）

用户阅读设置是「滚动模式」时，滚动渲染分支没有处理扫描版——即使导入成功，
打开后正文区也是空白（空 scroll-flow）。

**修复**：`isScroll && !isScanned` 才走滚动分支；扫描版始终走位图分支。

### 根因 3：翻页回调闭包读过期状态（src/pages/ReaderPage.tsx）

`turn` / `jumpToFraction` 的 `useCallback` 依赖列表不含 `isScanned` / `page`，
打开书后翻页回调闭包里是过期的 `isScanned=false` → 走 PageMap 分支 →
`pagemapRef.current` 为 null → **静默 return**，点按与进度条全部不翻页。

**修复**：扫描判定与当前页改读 ref（`scannedPagesRef` / 新增 `pageRef`），不再读闭包值。

### 验证

- 148 例单测通过；TypeScript 编译无错误。
- 浏览器实测：扫描版 PDF 导入成功、位图渲染清晰、翻页边界提示正常
  （「已经是最后一页了」/「已经是第一页」）、文字版 PDF 章节识别与正文可读。

## 修复二：扫描版位图底部被进度条遮挡（src/styles/theme.css + ReaderPage.tsx）

**现象**：扫描版 PDF 打开后，页面底部内容沉在悬浮进度条（底栏）下面，
且无法通过滚动看全。

### 根因

扫描版位图走 `.page-content` 容器，而该容器的布局规则是为**分页模式**设计的：
`position: absolute` + `top/bottom: 0` + `overflow: hidden`（固定一页高度，超出裁剪）。
扫描版一页位图约 1020px 高，远超视口 720px——

- 分页模式：图片底部被 `overflow: hidden` 裁掉 + 沉在底栏下面；
- 滚动模式：`.page-content` 被钳在视口高度里，`.page-viewport` 的 `scrollHeight`
  等于 `clientHeight`（实际不可滚），同样看不全。

### 修复

1. **ReaderPage.tsx**：扫描版位图的容器加 `scan-page` 修饰类
   （`<div className="page-content scan-page">`）；
2. **theme.css**：新增 `.page-content.scan-page` 规则——
   - `position: static` + `bottom: auto` + `overflow: visible`：解除分页模式的
     一页钳制，容器在文档流内自然生长，滚动交给 `.page-viewport.scroll-mode`；
   - 图片限高 `max-height: calc(100dvh - 168px)`（168px = 顶栏 64 + 底栏 104 的
     悬浮工具栏预留）：分页模式视口不可滚，整页缩进一屏完整显示；
     滚动模式下同样适用，保证任何情况下页面底部都不沉到进度条后面。

### 验证（浏览器实测，1224×1584 位图、视口 720px）

| 模式 | 修复前 | 修复后 |
| --- | --- | --- |
| 分页 | 图片底边 1084px，沉到底栏（顶 642px）下 441px | 图片限高 552px，底边 616px，完整可见（余量 26px） |
| 滚动（滚到底） | 视口不可滚，图片底部被裁 | 滚到底后图片底边 616px，完整可见（余量 26px） |

## 修复三：Ctrl+滚轮放大后字迹被压扁（字体变形）

**现象**：扫描版放大到 ×2 以上，整页被压成"横向条纹"——字被纵向压扁、糊成一片，
越放大越看不清（用户原话："不要让字体变形，Ctrl+滚轮实现整体放大"）。

### 根因（三处叠加）

1. **CSS 与内联样式抢尺寸**：`zoom > 1` 时 img 走内联 `width: 源宽×倍数; height: auto`，
   但 `.page-content.scan-page img` 的 `max-height: calc(100dvh - 168px)` 仍在生效。
   浏览器在"已定宽"的前提下单独压低高度 → 图片纵向压扁。
   实测 ×2.5：源图 1836×2376（比例 0.773）被显示成 **4590×552（比例 8.32）**，压扁 10 倍。
2. **缩放基准错**：`width = p.width * zoom` 把源图像素当基准，而"适应视口"本身
   已经缩小过一次 —— ×1 到 ×1.5 的实际变化与用户预期不符（×2.5 时 4590px 远超任何视口）。
3. **放大后横向不可达**：容器 `max-width: 840px` + 图片 `margin: 0 auto`，
   4590px 的图在 840px 容器里居中，左右两侧各溢出 1875px，而横向滚动上限只有 3563px ——
   图片右边缘永远滚不到。

### 修复

1. **新增 `src/core/scanView.ts`（纯函数 + 22 例单测）**：
   - `scanBoxFromViewport` 从视口尺寸与容器内边距算可用内容区；
   - `scanFitScale` 取宽高约束的小者（上限 1，小图不拉糊）；
   - `computeScanView` 用**同一个系数**同时算宽与高 —— 比例恒等于源图，任何 zoom 都不变形；
     缩放基准改为"适应视口"，×2 就是屏幕上的两倍大，与源分辨率解耦；
   - `zoomAnchor` / `scrollToAnchor` 记录并复原"光标下那一点"的相对位置，缩放不跑偏。
2. **ReaderPage.tsx**：
   - 位图显示尺寸改由 `computeScanView` 算出后写成内联 `width/height`，CSS 不参与；
   - 容器改为 `.page-viewport.scan-mode`（`overflow: auto`），横向纵向都能滚，
     且容器 `max-width: none` 让放大的图有地方去；
   - Ctrl/Cmd+滚轮统一为"阅读区整体放大"：扫描版走位图缩放（并按光标锚定滚动），
     文字版走字号档位 —— 都不改浏览器缩放级别；
   - 缩放倍数、光标锚点各留 ref 镜像：wheel 连续触发时 state 未落地，读 ref 才不丢档。
3. **theme.css**：删除 `.page-content.scan-page img` 的 `max-width` / `max-height`
   与 `:has(...[style*='max-width: none'])` 选择器 —— 只要留一条钳制规则，
   位图就会被"定宽 + 压低高"二次加工，这正是变形的根。位图只保留居中与 `object-fit: contain`。

### 验证（浏览器实测，源图 1836×2376，视口 1280×720）

| 档位 | 显示尺寸 | 显示比例 | 源比例 | 横向滚动 | 纵向滚动 |
| --- | --- | --- | --- | --- | --- |
| 适应 | 415×537 | 0.7736 | 0.7727 | — | — |
| ×1.5 | 640×828 | 0.7729 | 0.7727 | — | 276px |
| ×2 | 853×1104 | 0.7726 | 0.7727 | — | 552px |
| ×3 | 1280×1656 | 0.7729 | 0.7727 | 41px | 1119px |
| ×4 | 1706×2208 | 0.7726 | 0.7727 | 467px | 1671px |

- 每一档的宽高比都与源图一致（旧实现在 ×2.5 是 8.32，压扁 10 倍以上）；
- ×4 时光标所指的那一点在缩放前后停在同一处（rx 0.4696→0.4696，ry 0.4286→0.4286）；
- ×4 时左边缘 26px、右边缘滚到底正好对齐 1265px 视口右边，左右都能看全；
- 文字版（EPUB）Ctrl+滚轮：字号 18 → 20 → 22，浏览器 devicePixelRatio 恒为 1（不触发浏览器缩放）；
- 窗口尺寸变化后位图自动重新适应（视口 820×980 → 位图 627×812，比例仍 0.7722）。
