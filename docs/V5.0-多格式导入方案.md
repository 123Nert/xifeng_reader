# xifeng 阅读 · V5.0 多格式导入方案

> 目标：从"TXT 阅读器"升级为"**多格式本地阅读器**"——EPUB 为核心，兼容 Markdown / HTML，并补齐
> 批量导入、封面、真实章节目录等配套能力。
>
> 关联：《产品设计文档.md》（§3 非目标中"EPUB 不支持"在本版解禁）、《技术方案.md》（分页与存储架构）、
> 《功能迭代计划.md》（V5.0 占位）。

## 1. 格式可行性调研（决定范围的关键）

在写代码前先验证"浏览器零依赖能否做到"，结论如下：

| 格式 | 可行性 | 依据 | 结论 |
| --- | --- | --- | --- |
| **TXT** | ✅ 已支持 | 编码探测 + 单文本流 | 保留 |
| **EPUB** | ✅ **可行** | EPUB = ZIP + XHTML + OPF 清单；ZIP 可用 `DecompressionStream('deflate-raw')` 解压（现代浏览器与 Node 18+ 均内置），OPF/XHTML 用轻量解析即可 | **本版实现** |
| **Markdown** | ✅ 可行 | 纯文本 + 标记语法，去标记即得正文；`#` 标题可直接作为章节 | 本版实现 |
| **HTML** | ✅ 可行 | 标签剥离 + 标题识别（用自研轻量解析，避免依赖 DOMParser 以便两端可测） | 本版实现 |
| **PDF** | ❌ 不可行 | 文本抽取需要解析内容流、字体 CMap、编码映射，还要重建阅读顺序；零依赖做不"好"，引入 pdf.js 则是 1MB+ 的重依赖 | **明确不做**（见 §7） |
| **MOBI / AZW3** | ❌ 不做 | 亚马逊私有格式，结构复杂且无公开规范，工具链几乎全是 Python/Calibre 生态 | 不做 |

**关键架构结论**：EPUB 虽然是"多文件"格式，但导入时**把所有章节按顺序拼成单文本流，并记录每章起始字符偏移**——
这样 PageMap 的分页引擎（字符偏移坐标系）、进度、书签、批注、搜索**全部零改动复用**。
图片不进入正文（保持纯文本阅读体验与分页模型），仅提取封面用于书库展示。

> 为什么不做"按需加载章节"？我们的分页引擎本就支持百万字单串文本（实测 76 万字流畅），
> 一本 EPUB 通常 20–80 万字，全量拼接远比惰性加载简单，且能让搜索/批注跨章节工作。

## 2. 统一导入管线

```
文件 → 格式探测（扩展名 + 魔数）→ 对应 Importer → ImportResult → 入库
```

```ts
interface ImportResult {
  title: string
  text: string                 // 拼接后的单文本流
  format: BookFormat           // 'txt' | 'epub' | 'md' | 'html'
  charset?: string             // TXT 专有
  cover?: string               // 封面 data URL（EPUB 提取）
  tocEntries?: { title: string; charIndex: number }[]  // 真实目录（EPUB/HTML/MD）
  meta?: { author?: string; language?: string }
  warnings: string[]           // 局部失败的报告（如某章解析失败）
}
```

- **格式探测**：先看魔数（`PK\x03\x04` → EPUB/ZIP；`%PDF` → 明确报"不支持 PDF"并给出建议），
  再看扩展名，最后回退 TXT 尝试解码。**不给用户猜的机会，也不静默失败**。
- **局部容错**：EPUB 某章 XHTML 损坏时跳过该章并记入 `warnings`，其余章节照常导入——
  一本 100 章的书不应因 1 章损坏而拒绝导入。
- **失败可读**：所有错误提示用中文说明原因与下一步（如"这看起来是 PDF，目前仅支持 TXT/EPUB/MD/HTML"）。

## 3. EPUB 解析细节

### 3.1 ZIP 读取（零依赖）

1. 从文件尾向前搜 EOCD 签名 `0x06054b50`，读出中央目录偏移与条目数；
2. 遍历中央目录（签名 `0x02014b50`），记录每个条目的：名称、压缩方式、压缩/原始大小、本地头偏移；
3. 读取本地头（签名 `0x04034b50`）跳过变长文件名与 extra 字段，定位数据区；
4. 压缩方式 8（deflate）→ `DecompressionStream('deflate-raw')`；方式 0（stored）→ 直接切片；
5. **ZIP64 容错**：遇到 `0xFFFFFFFF` 哨兵值时读取 ZIP64 extra 字段；不支持时报可读错误而非崩溃。

> 实现要点：`DecompressionStream` 是流式的，小文件直接 `new Response(stream).arrayBuffer()` 收集结果更简洁。

### 3.2 OPF / 目录 / 正文顺序

1. 读 `META-INF/container.xml` → 拿到 `.opf` 路径（**唯一可信的入口**，不能假设文件名）；
2. 解析 OPF：
   - `manifest`：id → href / media-type（用于定位章节与封面）；
   - `spine`：**阅读顺序**（itemref 的 idref 序列）——这是章节的权威顺序；
   - `metadata`：`dc:title`、`dc:creator`（作者）、`dc:language`；
3. 目录（用于章节标题，优先级从高到低）：
   - EPUB 3：`properties="nav"` 的 nav 文档（XHTML 里的 `<nav epub:type="toc"><ol><li><a href>`）；
   - EPUB 2：`toc.ncx`（`navMap/navPoint/navLabel/text` + `content/@src`）；
   - 都缺失时：用章节文档里的 `<h1>~<h3>` 标题，或回退"第 N 章"；
4. 正文抽取：XHTML → 文本
   - 移除 `<script>/<style>/<head>`；
   - 块级标签（`p/div/br/h1-6/li/tr`）转换为换行；
   - 剥离其余标签，解码实体（`&nbsp; &amp; &lt; &#x…;` 等）；
   - 折叠多余空行（≥3 连续换行压成 1 个空行）。

### 3.3 章节拼接与偏移

```
第一回 灵根育孕源流出    ← 章节标题作为一行插入（保证 TOC 偏移稳定）
（章节正文…）
（空行）
第二回 悟彻菩提真妙理
（章节正文…）
```

每章插入标题行并记录 `charIndex`，得到与 PageMap 完全同坐标系的 `tocEntries`。
**阅读页优先使用导入目录**，无导入目录时回退到现有的正则切分（V1.1 能力保留）。

### 3.4 封面提取

- 优先级：OPF `meta[name="cover"]` → manifest 中 `properties="cover-image"` 的项 → 第一个图片资源；
- 图片转 data URL 存入书籍记录（体积通常 < 300KB，IndexedDB 无压力）；
- 书库卡片优先渲染真实封面，无封面时回退现有渐变封面。

## 4. 其他格式

### 4.1 Markdown
- `#`/`##`/`###` 标题 → 章节（`tocEntries`）；
- 去掉行内标记（`**粗体**`→粗体、`` `code` ``、`[文字](url)`→文字、图片语法移除）；
- 代码块（``` 围栏）原样保留内容，去掉围栏行；
- 引用 `>` 与列表 `-`/`1.` 去掉前缀保留内容。

### 4.2 HTML
- 与 EPUB 的 XHTML 抽取共用同一实现（`htmlToText`）；
- `<h1>~<h3>` 作为章节标题；`<title>` 作为书名兜底。

## 5. 配套能力（本版一并交付）

| 能力 | 说明 | 价值 |
| --- | --- | --- |
| **批量导入** | 文件选择与拖拽均支持多文件；逐个导入并显示进度；单个失败不影响其余 | 一次导入整套书 |
| **格式标签** | 书库卡片显示 TXT / EPUB / MD / HTML 角标 | 一眼区分来源 |
| **真实封面** | EPUB 封面提取并展示（无封面回退渐变） | 书库观感 |
| **导入进度** | 大 EPUB 解析时显示"正在解析…（第 N 章）" | 消除"卡死"错觉 |
| **作者信息** | 从 OPF 提取 `dc:creator`，书库与阅读页顶栏展示 | 书籍元信息 |
| **不支持格式的明确提示** | PDF/MOBI 等给出"暂不支持"而非"导入失败" | 降低困惑 |

## 6. 数据模型变更（DB v6）

```ts
// BookRecord 扩展（均为可选，老记录天然兼容）
format?: BookFormat                    // 缺省视作 'txt'
cover?: string                         // data URL
tocEntries?: { title: string; charIndex: number }[]   // 导入目录（优先于正则切分）
author?: string
language?: string
```

- **无需建新 store**：仍写入 `books`，升级零迁移成本（老记录缺字段，读取时按缺省处理）；
- 备份导出/导入已包含完整 `books` 记录，**多格式书籍与封面自动随备份迁移**，无需改动备份逻辑。

## 7. 明确不做

| 项 | 原因 |
| --- | --- |
| **PDF** | 文本抽取需解析内容流/字体 CMap/编码映射并重建阅读顺序；零依赖做不好，引入 pdf.js（1MB+）违背"零依赖"原则。若未来要做，应单独立项并评估重依赖 |
| **MOBI / AZW3** | 亚马逊私有格式，无公开规范 |
| **EPUB 内嵌图片** | 会让"纯文本单串 + 字符偏移"的分页模型失效（图片高度参与排版），且破坏 V4.0 批注的字符锚定。保留为未来议题 |
| **DRM 加密 EPUB** | 法律与技术双重障碍（加密 EPUB 的正文是加密的，无解密能力） |
| **固定版式 EPUB**（fixed-layout） | 面向画册/漫画，与流式阅读模型冲突；导入时检测到则警告并尽力提取文本 |

## 8. 分期与规模

| 阶段 | 内容 | 规模 |
| --- | --- | --- |
| **V5.0-a 导入管线** | `core/importers/` 统一接口 + 格式探测（含魔数）+ 批量导入 + 格式标签 + 错误提示 | M |
| **V5.0-b EPUB** | ZIP 读取（含 ZIP64 容错）+ OPF/spine/nav/ncx 解析 + XHTML 文本抽取 + 章节拼接与目录 + 封面提取 | L |
| **V5.0-c MD / HTML** | Markdown 与 HTML 抽取（与 EPUB 共用 `htmlToText`）+ 标题识别为目录 | M |
| **V5.0-d 配套** | 导入进度反馈、作者信息、书库封面渲染、阅读页使用导入目录 | M |

每阶段独立可用：a 完成后批量导入即生效；b 完成后可读 EPUB；c 完成后覆盖文档类；d 完成后体验完整。

## 9. 验收标准

1. 导入一本**中文 EPUB**：正文完整无乱码，章节数与原书一致，目录可跳转，顶栏显示当前章节；
2. 导入 **Markdown 与 HTML**：正文可读，`#`/`<h1>` 标题进入目录；
3. **原有能力零回归**：TXT 导入、编码识别、分页/滚动、进度续读、书签、搜索、批注、导出全部照常工作；
4. 一次选择**多个文件**可批量导入，单个文件失败不阻断其余；
5. EPUB 封面在书库中正确显示，无封面时回退渐变封面；
6. 导入 PDF/MOBI 时给出明确的"暂不支持"提示而非通用错误；
7. 损坏的 EPUB（缺 container.xml / OPF 缺失 / 单章损坏）给出可读错误或跳过坏章继续导入，不崩溃；
8. 多格式书籍的进度、书签、批注与备份导出/导入全部正常。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| ZIP 解析边界情况（ZIP64、数据描述符、非标准压缩） | EPUB 打不开 | 覆盖 ZIP64 extra 字段解析；遇到数据描述符（本地头 size 为 0）时改用中央目录的 size；单测覆盖上述构造 |
| `DecompressionStream` 老浏览器缺失 | EPUB 不可用 | 检测能力，缺失时明确提示"浏览器过旧"，TXT/MD/HTML 不受影响 |
| XHTML 结构千奇百怪（命名空间、嵌套表格、注释） | 文本抽取错乱 | 正则剥离 + 块级标签换行 + 实体解码；用真实 EPUB 与构造样本双路测试 |
| 章节标题重复（如多卷同回目） | 目录跳转歧义 | 目录以 `charIndex` 为主键（唯一），标题仅用于显示 |
| 大 EPUB 解析耗时 | 界面卡顿 | 解析按章进行并在 UI 上显示进度；单本 5MB EPUB 实测目标 < 1s |
| 老记录缺 `format` 字段 | 书库渲染异常 | 读取层缺省为 `'txt'`，渲染时兜底 |

## 11. 演进预留

- **EPUB 内嵌图片**：若未来要做，方案是"图片作为独立分页单元"（PageMap 引入非文本元素），需先改分页模型；
- **PDF**：单独立项，评估 pdf.js 依赖成本与只读文本层方案；
- **多格式导出**：把批注笔记导出为 EPUB/HTML（当前为 Markdown）；
- **书库分组**：按格式/作者分组，书目量大后的自然需求。
