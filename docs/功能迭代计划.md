# xifeng 阅读 · 功能迭代计划

> 以《产品设计文档.md》§5 迭代路线为骨架（V1.1 / V1.2 命名与其保持一致），
> 参照主流优秀阅读器的成熟体验，展开为一份可排期、可验收的功能计划。
> 技术落点均对齐《技术方案.md》的架构（core 纯逻辑层 + PageMap 字符偏移坐标系 + CSS 变量主题）。

## 1. 计划原则

1. **本地优先**：所有功能不引入服务端依赖；云同步是唯一例外且排在最后。
2. **架构不破**：新增功能优先落在 core 层的既有复用点上；需要动架构的（滚动模式、EPUB）单独立项评估。
3. **闭环不破**：每期交付后，"导入 → 阅读 → 续读"的核心闭环必须完好，全部测试通过（AGENTS.md 约定）。
4. **对标克制**：只抄"本地阅读"场景下真正高频的体验，不跟进社交与生态类功能。

## 2. 对标分析：值得借鉴的体验

| 软件 | 标志性亮点 | 本产品借鉴 | 明确不跟进 |
| --- | --- | --- | --- |
| 微信读书 | 排版细腻（字号/行距/边距/段距）、主题丰富、听书、阅读时长统计 | 主题体系、排版设置粒度、阅读统计口径 | 想法/共读/排名等社交 |
| Kindle | 位置（location）即字符偏移、X-Ray、自定义字体 | 位置模型（PageMap 与其同构，已完成）、两端对齐、自定义字体 | 商店、推送、生词本 |
| 静读天下 Moon+ Reader | 本地 TXT 排版选项最全、替换净化、滚屏模式、阅读统计、音量键翻页 | 净化规则、滚屏、统计、排版粒度 | 广告 SDK、复杂手势体系 |
| Legado（阅读 3.0） | 章节正则**用户可自定义**、替换规则可导入导出、开源 | "第X章"切分正则开放自定义 + 规则分享 | 在线书源（版权风险高） |
| KOReader | 阅读统计精细（每页速度）、自动翻页 | 统计维度设计、自动滚屏 | 硬件/固件适配 |
| Apple Books | 分页 / 连续滚动双模式、阅读目标 | 双模式切换交互（远期） | 生态绑定 |

## 3. 功能分期清单

规模：S ≈ 半天内，M ≈ 1–3 天，L ≈ 1 周以上（业余节奏）。

### V0（MVP，已完成 ✅）

导入 / 编码识别 / 书库 / 分页阅读 / 字号行距 / 进度记忆 / 进度条跳转 —— 全部验收通过。

## 4. 不做清单（在 MVP 非目标基础上更新）

- **在线书源 / 网络文学聚合**：版权风险，与"本地阅读器"定位冲突（Legado 的书源体系不学）
- **社交功能**：想法、共读、排行榜、赠书
- **账号体系**（除非云同步立项）
- **移动端专属 tricks**：音量键翻页、手势调亮度（桌面 Web 优先，移动 Web 可后续评估）
- **AI 功能**（摘要/问答）：等生态与成本明朗后再评估

## 5. 技术风险与预研点

| 风险 | 影响功能 | 对策 |
| --- | --- | --- |
| 自定义字体异步加载：`FontFace` 加载完成前分页测量用的是回退字体，页界会错 | V1.3 字体选择 | 监听 `document.fonts.ready` 后强制一次 reflow；探针与正文同字体已由 CSS 变量保证 |
| 滚动模式与 PageMap 分页坐标系冲突 | V2.1 滚动模式 | 进度统一存字符偏移；滚动模式单独建"偏移→页界"映射层，两模式经字符偏移互转，不动存储模型 |
| EPUB 打破"整本一个字符串"假设 | V3.0 EPUB | 章节资源化加载 + 按章拼接虚拟文本流；先立项技术方案 |
| 正则章节切分的误切（数字开头的普通段落） | V1.1 目录 | 内置正则保守起步 + 用户可自定义；切分结果可视化预览再确认 |
| 全文搜索在超长文本的卡顿 | V1.2 搜索 | 单次 `indexOf` 扫描本身很快；结果列表分页渲染即可，无预建索引 |

## 6. 节奏与交付约定

- 按版本号推进，一期 1–2 周（业余节奏）；每期收尾：全部测试通过 → 更新两份既有文档中受影响的章节 → 打 git tag（如 `v1.1.0`）。
- 每个功能独立 commit 链，遵循 AGENTS.md（改动 + 测试 + 提交）。
- 每期上线前跑一遍"验收清单"：导入 UTF-8/GBK → 阅读翻页 → 退出重开续读 → 跳转 → 主题/排版设置生效，确保核心闭环始终可用。
