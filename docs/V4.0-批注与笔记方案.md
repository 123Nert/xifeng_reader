# xifeng 阅读 · V4.0 批注与笔记体系方案

> 背景：V3.0 交付的划线功能是"能用但很薄"——选中文字后只有单一动作（划线）、只有一种配色（绿色），
> 不能写想法，也无法改色、改样式或管理。本文档基于对主流阅读器的调研，给出完整的批注与笔记体系设计。
>
> 关联文档：《产品设计文档.md》（§5 迭代路线）、《技术方案.md》（分页/存储架构）、《功能迭代计划.md》（V4.0 占位）。

## 1. 调研结论

### 1.1 对标一手资料

调研采取"读实现而非读介绍"的方式，重点参考两类一手资料：

**KOReader 源码**（`frontend/apps/reader/modules/readerhighlight.lua`、`readerannotation.lua`）——本地 TXT/EPUB 阅读器的标杆，与我们的场景最接近。关键发现：

| 发现 | 源码依据 | 对我们的启示 |
| --- | --- | --- |
| **9 种内置颜色**：red / orange / yellow / green / olive / cyan / blue / purple / gray | `highlight_colors` 表 | 颜色不是"装饰"，而是**语义编码**；数量要够用能让用户建立自己的配色习惯 |
| **支持用户自定义颜色**（名称 + 色值），持久化在设置里 | `custom_colors`、`getHighlightColorList()` | 自定义色是进阶需求，MVP 可先给固定色板 + 后续开放自定义 |
| **4 种标注样式**：highlight（高亮底色）/ underline（下划线）/ strikeout（删除线）/ note（纯批注） | `highlight_style` 表 | 样式与颜色正交：同一颜色可配不同样式，表达不同语义 |
| **深色模式颜色自适应**（夜间模式自动反色处理） | `getHighlightColorCode(..., honor_night_mode)` | ⚠️ 我们已有 3 套主题，**每个主题必须有独立标注色板**，否则夜间模式下高亮刺眼 |
| **重叠标注选择对话框**：点击重叠区域时列出所有重叠标注供选择 | `showChooseHighlightDialog` | 这是最容易被忽略的工程难点，必须专门设计 |
| **跨页标注降级策略**：多页高亮只恢复第一页的框 | `-- multi-page highlight, restore the first box only` | 允许标注跨页，渲染按当前页裁剪 |
| **批注字段完整**：`text / note / chapter / datetime / datetime_updated / drawer(样式) / color / pos0 / pos1` | `readerannotation.lua` | 数据模型参考：**章节归属 + 创建/修改时间 + 样式分离** |
| **导出 Markdown**（`note_format = "md"`）、页面上有批注视觉标记（`note_mark`） | — | 导出与"书页内可见性"都要做 |

**W3C Web Annotation Data Model**（W3C Recommendation）——批注数据模型的权威标准：

| 概念 | 说明 | 对我们的启示 |
| --- | --- | --- |
| `Annotation` = `target` + `body` | target 是被标注的文本范围，body 是标注内容（评论/标签） | 划线（highlight）与想法（comment）是**同一个批注的两个部分**，不是两种东西 |
| `motivation` / `purpose` | 标注意图：highlighting / commenting / bookmarking / tagging | 颜色可以承载 motivation 语义（如"重点/疑问/金句"） |
| **`TextPositionSelector`**（起止偏移） | 我们当前用的方式 | 快，但**正文一旦变化就全部失效** |
| **`TextQuoteSelector`**（引用文本 + 前后文） | `exact` + `prefix` + `suffix` | ⭐ **容错锚定**：正文变化后可重新定位；一个批注可**同时持有两种 selector**，互为备份 |
| `RangeSelector` | 组合多个 selector 表达复合范围 | 跨段落/跨页标注的标准做法 |

**Readwise**（笔记聚合工具，代表"标注的二次价值"）：
- 强调**颜色即标签**：用户可为每种颜色赋予含义，并可作为标签导出；
- 支持"创建即打标签"（Tag your highlights as you make them）、高亮串联（concatenation）；
- **间隔复习**（Daily Review / Themed Review）：让标注产生长期价值；
- 导出面向 Notion / Obsidian / Evernote 等笔记生态。

**微信读书**（中文大众场景标杆）：划线与"想法"分离（划线=原文标记，想法=个人评论），想法可公开/私密；"热门划线"显示他人标注数；导出笔记带章节结构。

### 1.2 我们的现状与差距

| 能力 | 现状（V3.0） | 目标（V4.0） |
| --- | --- | --- |
| 颜色 | 仅 1 种（固定绿色，`--hl-bg`） | 6 色可选，各主题独立色板，可自定义含义 |
| 样式 | 仅高亮底色 | 高亮 / 下划线 / 波浪线（+ 删除线） |
| 想法 | 数据结构有 `note` 字段但**无输入入口** | 完整输入/编辑/展示闭环 |
| 重叠标注 | 未处理（渲染已支持切割，但点击无区分） | 点击重叠处弹出选择；可编辑任一条 |
| 锚定 | 仅字符偏移 | 偏移 + 前后文引用（容错重定位） |
| 管理 | 平铺列表、可删除 | 按章节分组、按颜色/有笔记筛选、搜索、跳转 |
| 导出 | Markdown（扁平） | 章节分组 + 颜色标签 + 想法 + 时间，Obsidian 友好 |
| 触屏 | 桌面鼠标拖选 | 长按选字 + 移动端适配 |

## 2. 设计目标

1. **一次选中，三个动作**：选文字 → 直接点颜色（高亮）/ 点样式（下划线、波浪线）/ 写想法。
2. **颜色即语义**：默认 6 色，用户可给颜色命名（如"重点""疑问""待查"），形成个人编码体系。
3. **想法是主体**：不只记录"我划了这句"，而是"我为什么划这句"。
4. **标注不丢**：三层容错（字符偏移 → 前后文引用 → 章节近似定位），即便正文被重新净化或重导也能找回。
5. **晚上不刺眼**：三套主题各有独立标注色板，夜间模式下自动切换柔和色。

## 3. 数据模型（DB v5）

### 3.1 记录结构

```ts
interface HighlightRecord {
  id: string
  bookId: string
  // ---- 锚定（三层容错，见 §3.3）----
  start: number          // 字符偏移（现有）
  end: number
  prefix?: string        // 选区前 24 字（TextQuoteSelector 思想）
  suffix?: string        // 选区后 24 字
  chapterIndex?: number  // 所属章节目录序号（便于分组与近似重定位）
  // ---- 展示 ----
  text: string           // 原文摘录（现有）
  color: ColorName       // 新增：yellow | green | blue | pink | purple | orange
  style: MarkStyle       // 新增：highlight | underline | squiggly | strikeout
  // ---- 笔记 ----
  note?: string          // 想法正文（现有字段，本次补齐输入 UI）
  tags?: string[]        // 预留：标签（V4.1）
  // ---- 元信息 ----
  createdAt: number
  updatedAt?: number     // 新增：修改时间
}

type ColorName = 'yellow' | 'green' | 'blue' | 'pink' | 'purple' | 'orange'
type MarkStyle = 'highlight' | 'underline' | 'squiggly' | 'strikeout'
```

### 3.2 数据库迁移（v4 → v5）

```ts
// bookRepository.getDB() upgrade 分支
if (oldVersion < 5) {
  // 无需建新 store：highlights 仍是同一 store，仅补字段默认值
  // 老记录（V3.0 创建）缺 color/style，读取时归一化：
  //   color: r.color ?? 'green'（保持与旧视觉一致，用户无感）
  //   style: r.style ?? 'highlight'
  // 归一化放在读取层（normalizeHighlight），不改写用户数据，
  // 保证"回退旧版本仍可读"。
}
```

**迁移原则**：读取层归一化而非批量改写——用户数据只在用户主动操作时写入，避免升级即改库的风险。

### 3.3 锚定与容错重定位

参考 W3C 的"多 selector 并存"：

| 层 | 手段 | 用途 |
| --- | --- | --- |
| L1 | `start/end` 字符偏移 | 正常情况（正文未变），O(1) 命中 |
| L2 | `prefix + text + suffix` 引用匹配 | 正文被重新净化/重导后，用 `indexOf(prefix + text + suffix)` 就近搜索；失败则退化到 `indexOf(text)`，多处命中时取与 L1 偏移最接近的一个 |
| L3 | `chapterIndex` | 以上全失败时，仅在所属章节范围内搜索，仍失败则标记"位置待确认"并在列表中以章节名展示（不丢内容） |

触发时机：书籍重新导入（内容变更）时后台重定位；也可在笔记面板提供手动"修复位置"入口。

## 4. 交互设计

### 4.1 选中态工具栏（核心改造）

选中文字后，选区上方浮出一横条（替代当前单一"划线"按钮）：

```
┌──────────────────────────────────────┐
│ ● ● ● ● ● ●  │  下划线  波浪线  │ ✎ 写想法 │
│ 黄 绿 蓝 粉 紫 橙                    │
└──────────────────────────────────────┘
```

- 点色块 = 立即以默认样式（高亮）标注；
- 「下划线」「波浪线」= 以当前默认色 + 对应样式标注；
- 「✎ 写想法」= 先建标注，随即弹出想法输入层；
- 记忆上次使用的颜色与样式（KOReader 的 `saved_color`/`saved_drawer` 同思路）。

### 4.2 已有标注的编辑

点击正文中的标注 → 弹出编辑卡（锚定在标注附近）：

```
┌────────────────────────────────┐
│ "……群山如黛，江水无声……"      │
│ ─────────────────────────────  │
│ 换色：● ● ● ● ● ●              │
│ 样式：高亮 / 下划线 / 波浪线   │
│ 💭 我的想法：____________      │
│ [复制原文] [删除]              │
└────────────────────────────────┘
```

**重叠标注**：点击处命中多条时，编辑卡顶部显示可切换的标注条（`1/3`）——参考 KOReader 的 `showChooseHighlightDialog`，但用更轻的"切换条"而非对话框。

### 4.3 想法输入

- 桌面：编辑卡内联 textarea，输入即存（防抖 500ms），Esc 收拢；
- 移动端：底部抽屉全宽输入，带键盘避让；
- 想法非空时，标注右侧渲染一个小标记（💭 或圆点），提示"这条有想法"。

### 4.4 笔记面板（ReaderMenu「笔记」页签升级）

```
[全部] [黄] [绿] [蓝] [粉] [紫] [橙] [💭有我写的]    共 42 条
─────────────────────────────────────────────
第一回 灵根育孕源流出            6 条
  ▎黄 · 高亮   地辟于丑。又经五千四百岁……
    💭 这里的宇宙观值得记一笔
  ▎绿 · 波浪线 天开于子，地辟于丑……
第二回 悟彻菩提真妙理            3 条
  ...
```

- 按章节分组（用 `chapterIndex` 关联目录）；
- 顶部筛选条：按颜色、按"有想法"、按样式；
- 每条显示：颜色条、样式图标、原文、想法、时间；
- 点击条目 → 跳转正文并**高亮闪烁**该标注（区别于普通跳转）；
- 长按/右键条目 → 编辑想法 / 改色 / 删除。

### 4.5 移动端适配

- 长按选字：`touchstart` + 计时（400ms）进入选择模式，或依赖系统原生选字手势（iOS/Android 均支持）；
- 工具栏宽度自适应，色块尺寸放大到 ≥40px 触控区；
- 编辑卡改为底部抽屉。

## 5. 渲染实现要点

### 5.1 多样式的 CSS 表达

```css
/* 高亮：底色（各主题独立色板） */
[data-theme='light'] { --hl-yellow: #ffe9a8; --hl-green: #cfe8db; /* ... */ }
[data-theme='sepia'] { --hl-yellow: #e8cf7a; /* ... */ }
[data-theme='dark']  { --hl-yellow: #55551f; --hl-green: #2f4a3c; /* ... */ }

.page-content mark.hl[data-color='yellow'] { background: var(--hl-yellow); }
.page-content mark.hl[data-style='underline'] {
  background: none;
  text-decoration: underline 2px var(--hl-yellow);
  text-underline-offset: 3px;
}
.page-content mark.hl[data-style='squiggly'] {
  background: none;
  text-decoration: underline wavy 1.5px var(--hl-yellow);
}
```

**关键**：标注颜色用 CSS 变量 + `data-color` 属性，主题切换零成本适配（夜间柔和色板）。

### 5.2 重叠标注的分段渲染（V3.0 已具备基础）

现有 `renderLine` 已实现"切割点集合 → 分段 → 按区间归属上色"的算法，V4.0 只需扩展：

1. 分段时记录每段归属的**全部**标注 id（数组，而非布尔）：`owners: string[]`；
2. 渲染时取"最上层"标注（最新创建的优先，或按样式优先级）决定视觉；
3. 给每个 `mark` 挂 `data-ids`，点击时用 `closest('mark').dataset.ids` 取出全部命中，驱动 §4.2 的切换条；
4. 多条标注的分段点合并用 `Set<number>` 排序（现有实现），复杂度 O(k·n)，k 为标注数，实测无压力。

### 5.3 跨页/跨段落标注

- 一条标注的 `start/end` 可跨越页边界与段落；
- 渲染时按当前渲染片段的 `[base, base+len)` 与标注区间求交集，只渲染可见部分（V3.0 的 `renderLine` 已按行裁剪，无需改动）；
- 目录跳转时，若目标标注跨页，跳转到**其起点所在页**。

## 7. 分期与规模

| 阶段 | 内容 | 规模 | 依赖 |
| --- | --- | --- | --- |
| **V4.0-a 标注基础** | 数据模型扩展（颜色/样式/前后文/章节）+ 读取层归一化迁移 + 6 色 × 4 样式渲染 + 各主题色板 + 选中态工具栏（点色即标） | M | 无 |
| **V4.0-b 想法** | 想法输入/编辑/展示（编辑卡 + 移动端抽屉）+ 标注列表带想法标识 + 想法在面板中的展示 | M | a |
| **V4.0-c 编辑与管理** | 点击已有标注 → 编辑卡（改色/换样式/改想法/删除）+ 重叠标注切换条 + 笔记面板筛选/分组/搜索 + 跳转闪烁 | M | a、b |
| **V4.0-d 容错与导出** | 三层锚定与重定位修复 + 导出升级（章节分组/图例/CSV/仅导出有想法） | M | a |
| **V4.1 进阶** | 颜色语义自定义（用户给颜色命名）+ 标签系统 + 快速标注手势（双击段落标记）+ 跨书笔记汇总视图 | L | V4.0 |
| **远景（V5）** | 间隔复习（Readwise 式 Daily Review）+ 笔记与 Obsidian 双向同步 + 公开分享标注 | L | V4.1 |

建议按 a → b → c → d 顺序交付，**每个阶段独立可用**：a 之后用户就能选颜色和样式，b 之后能写想法，c 之后能管理，d 之后抗风险与导出。

## 8. 验收标准

1. 选中文字后可直接点选 6 种颜色之一完成标注，颜色即时生效且在三种主题下都清晰、不刺眼；
2. 可标注为高亮/下划线/波浪线/删除线四种样式，样式与颜色可自由组合；
3. 任意标注都可附加想法，想法的增删改即时保存，重开应用不丢；
4. 点击已有标注可改色、换样式、改想法、删除；两条标注重叠时能明确选择要编辑哪一条；
5. 笔记面板按章节分组，可按颜色/有无想法筛选，可搜索想法内容，点击条目精确跳转并在正文中闪烁定位；
6. 导出的 Markdown 含章节分组、颜色图例与想法，可直接粘贴进 Obsidian 且有良好排版；
7. 删除书籍时其标注一并清除；备份导出/导入包含全部批注数据；
8. 正文重新净化重导后，已有批注能自动找回位置（三层锚定生效），失败时明确提示而非静默错位。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 重叠标注渲染复杂度 | 大量标注时每页重算 | 分段算法 O(k·n) 且只对当前页/窗口内的标注参与计算；必要时按页缓存分段结果 |
| 夜间模式下颜色刺眼 | 体验回归 | 三套主题各配独立色板（柔和低饱和），纳入验收标准第 1 条 |
| 正文变更导致标注漂移 | 数据价值受损 | 三层锚定（§3.3）+ 重定位失败时明确标记"位置待确认"，不静默错位 |
| 移动端选字体验碎片化 | 触屏用户难用 | 优先依赖系统原生选字，工具栏自适应放大；不自行实现复杂手势 |
| 功能膨胀 | 偏离"本地 TXT 阅读器"定位 | 明确不做：多人协作批注、公开社区划线（微信读书式社交）、AI 自动摘要批注 |
| 数据迁移出错 | 用户既有划线丢失 | 读取层归一化（不改库）+ 备份导入导出已含批注 + 迁移前建议用户导出备份 |

## 10. 明确不做

- **社交化批注**：公开想法、他人划线热度（微信读书的社交属性不跟进）
- **多人协作标注**：共享批注、评论回复
- **AI 批注**：自动生成摘要/解读（等成本与场景明朗后再评估）
- **富文本想法**：V4 只做纯文本想法（Markdown 语法可原样保存，导出时不转义）
