# xifeng 阅读 · V6.2 PDF 原版页面方案

> 背景：V6.0/V6.1 把 PDF 抽成纯文本（扫描版则预渲染成位图）。用户提出
> 「**PDF 文档导入不要只提取文字，要原来的 PDF 文档全部导入**」——
> 版式、图片、表格、公式都要在，读到的必须是"它原来的样子"。
>
> 本文给出落地方式、与既有架构的接缝，以及实测数据。

## 1. 方案选择

| 选项 | 存储 | 导入耗时 | 放大清晰度 | 结论 |
| --- | --- | --- | --- | --- |
| A. 导入时把每页转成位图入库（V6.1 扫描版做法） | 每页 200–600 KB，一本 300 页 ≈ 100 MB+ | 逐页 canvas 渲染，很慢 | 放大后是拉伸位图，越大越糊 | ❌ 只适合"没有文字层、别无选择"的扫描版 |
| B. 导入时转成单个 PDF 文件另存 | 同原文件 | 需要额外编码 | 同原文件 | ⚠️ 没有收益，还得引入 PDF 生成依赖 |
| **C. 原文件整份入库，阅读时按需渲染当前页** | **≈ 原文件大小**（几 MB） | **只抽文字，秒级** | **每次按当前显示尺寸重新渲染，×4 也是原生清晰度** | ✅ |

选 C。关键认知：**"保留原版"不需要预先把页面画出来**——
pdf.js 本来就能随时按任意倍率把某一页渲染成 canvas，
所以只要把**原文件字节**存好，阅读时想要多大就渲染多大。

## 2. 数据与流程

```
导入：ArrayBuffer ──┬─→ pdf.js 抽文字（既有通道）→ books.content（搜索/划线/朗读/分页）
                    ├─→ pdfFiles store（原文件字节）→ 阅读页按需渲染"原版页面"
                    └─→ pdfPageStarts（每页文字起始偏移）→ 页码 ↔ 字符偏移换算
```

一句话概括读法：**原文件整份入库，页面在你要看的那一刻按当前尺寸渲染**。
所以"原版"不是一张张预先存好的图，而是同一个文件在当下重新排出来的画面 ——
这样既省存储（几 MB 而不是几百 MB），放大时也不会糊（不是拉伸位图）。

- **新增 `pdfFiles` store**（DB 升到 v6，keyPath `bookId`）：存整份文件字节 + 大小。
  一本书一条记录，删书时一并清掉；备份导出时以 base64 带走，导入时还原。
- **不预渲染任何页面位图**：新导入的 PDF 不再产生 `pdfPages` 记录
  （该 store 保留，老库里的位图仍可读，阅读页自动兼容）。
- **导入不再依赖 canvas**：文字抽取本来就不需要 canvas，
  V6.1 的"扫描版必须逐页渲染"随之消失 —— 导入路径在 Node 里也能跑通
  （单测因此可以直接断言扫描版样本的导入结果）。

## 3. 阅读页：原版 / 文字 双视图

| 视图 | 显示什么 | 能做什么 |
| --- | --- | --- |
| **原版**（有原件的 PDF 默认） | pdf.js 实时渲染的整页位图，等比铺满视口 | 翻页、缩放（底栏 ＋/－ 或 Ctrl+滚轮，最高 ×4）、进度条、目录、书签 |
| **文字**（可切） | 既有的分页/滚动文本流 | 搜索、划线、批注、朗读、排版设置 |

- 纯扫描版 PDF（没有文字层）只有原版视图，搜索/朗读会明确提示不可用。
- 底栏「原版 / 文字」按钮切换视图，**位置按字符偏移带过去**，不回到开头：
  页码 ↔ 偏移的换算表由导入时记录的 `pdfPageStarts` 提供（见 `core/pdfNav.ts`），
  两套坐标系因此始终对齐，进度条 / 书签 / 目录跳转在任何视图下都自洽。

### 渲染细节（`core/pdfOriginal.ts`）

- `fitRenderScale(页宽, 页高, {显示宽, 高, dpr})`：按"位图要覆盖的显示尺寸 × DPR"
  算渲染 scale，并受像素总数（1200 万）与单边（4096）上限约束 ——
  超大页面（海报、图纸）不会撑爆 canvas；
- 每次只渲染当前页，结果按 `页号@尺寸` 缓存少量条目（LRU 6 条）；
- 新一轮渲染开始前取消上一轮（连点缩放不排队画图）；
- 离开阅读页销毁 pdf.js worker 与页面缓存。

## 4. 与既有能力的接缝

| 能力 | 原版视图 | 文字视图 |
| --- | --- | --- |
| 翻页 | 按 PDF 页（写入字符偏移进度） | PageMap 分页 |
| 进度条 / 续读 | ✅（同一个字符偏移坐标系） | ✅ |
| 目录 / 书签跳转 | ✅（跳转到该偏移所在的 PDF 页） | ✅ |
| 缩放 | 位图等比缩放（原生清晰度） | 字号档位 |
| 搜索 / 划线 / 批注 / 朗读 | ❌（有文字层时切文字视图即可） | ✅ |

## 5. 验收（浏览器实测，1280×720 视口）

| 场景 | 结果 |
| --- | --- |
| 导入文字版 PDF（sample-cn.pdf，3 页） | 秒级完成；书库徽章 `PDF · 3 页 · 原版可切换` |
| 打开 | 默认原版视图，显示第 1 页原貌（版式与 PDF 一致） |
| Ctrl+滚轮 / ＋ 放大 | 显示尺寸 390→586→781→1171px，位图**同步重渲染**（natural = display），比例恒为 0.7071（= 源页比例） |
| 翻页 | 点按/键盘/进度条都能翻；进度写入偏移 0 → 43 → 74（= 各页文字起点） |
| 切文字视图 | 落到"第三章 归途"（与当前原版页同一位置），搜索/划线/朗读恢复可用 |
| 切回原版 | 回到同一页，位置不丢 |
| 纯扫描版 PDF（sample-scan-only.pdf） | 导入成功（不再要求 canvas），只有原版视图，按页翻/缩放正常 |
| 老记录（V6.1 存的页位图） | 自动走旧位图通道，仍可阅读 |
| 续读 | 进度 74 → 重新打开直接落在原版第 3 页 |

## 6. 边界与取舍

- **存储**：一本 PDF 在库里占"原文件大小 + 抽出的文字"。100 MB 的 PDF 会让
  IndexedDB 明显变大 —— 这是"要原版"的必然代价；备份导出会连原件一起带上，
  体积也会变大（base64 约 +33%）。
- **内存**：只渲染当前页，且受像素上限约束；不整本预渲染。
- **纯图 PDF 的文字能力**：没有文字层就搜不了、划不了、读不了，
  与原版阅读二选一时选择了"先能看原样"（要 OCR 请先用专门工具处理）。
- **加密 / 损坏文件**：与 V6.0 一致，导入期即明确报错，不进库。
