# xifeng 阅读 · V6.0 PDF 支持方案

> 背景：《V5.0-多格式导入方案.md》§7 曾把 PDF 列为"明确不做"，理由是零依赖做不好文本抽取、
> 引入 pdf.js 是重依赖。本版重新评估后决定**做**，关键是找到不伤害现有优势的做法。

## 1. 决策依据（为什么现在做）

| 原判断 | 重新评估 |
| --- | --- |
| "零依赖做不好 PDF 文本抽取" | ✅ 仍然成立：内容流/字体 CMap/编码映射/阅读顺序重建四层问题无法用少量代码可靠解决 |
| "引入 pdf.js 是 1MB+ 重依赖" | ⚠️ 可用 **按需加载** 化解：只有真正打开 PDF 时才下载解析器，普通用户零影响 |
| "pdf.js 是渲染器，与纯文本模型不匹配" | ⚠️ 但我们只用它的 **textContent** 能力（不渲染 canvas），产出的仍是文本 |

**关键取舍**：PDF 的"页"是物理页面，与我们"字符偏移"的分页模型是两套体系。方案选择
**把 PDF 抽成单文本流**（与 EPUB 同思路），从而：

- ✅ 批注、想法、搜索、TTS、进度续读、排版设置**全部照常可用**（它们都基于字符偏移）
- ✅ 分页引擎零改动
- ❌ 丢失 PDF 的原始版式、图片、表格排版（换来的是"能舒服地读"，而非"忠实还原"）
- ❌ 扫描版 PDF（整页图片）无法处理 → V6.1 起改为按页位图阅读（见 §3.3）

## 2. 依赖与体积

- 依赖：`pdfjs-dist`（Mozilla 官方，Apache-2.0）
- 体积：核心 448K + worker 1.3M（gzip 后约 500K 合计）
- **加载策略：动态 import**——`src/core/importers/pdf.ts` 及其 pdf.js 依赖只在
  "用户真的打开了一个 PDF" 时才加载。构建产物中它们是独立 chunk，常规用户（TXT/EPUB）完全不受影响。

## 3. 文本抽取管线

```
PDF 文件 → pdf.js getDocument → 逐页 getTextContent → 组装行与段落 → 拼接单文本流 → 入库
```

### 3.1 行与段落组装（核心，纯函数可测）

pdf.js 的 `getTextContent()` 返回的是**带坐标的文本片段**（item），不保证行/段结构：

```js
{ str: '第一章', width: 42, height: 14, transform: [14,0,0,14,50,800], hasEOL: false }
                                                         ↑x  ↑y
```

组装规则：
1. **同一行判定**：`y` 基本相同（差值 < 2pt）→ 属同一行；
2. **行内拼接**：直接相连；若片段间存在水平间隙（> 0.25 × 字号）**且两侧都不是 CJK 字符**，
   插入一个空格（中文排版不需要空格，英文单词间需要）；
3. **换行**：`hasEOL` 标记 或 `y` 变化 → 结束当前行；
4. **段落间隔**：相邻行的 `y` 间距 > 1.6 × 常规行距（行距由全文行距的中位数估计）→ 插入空行。

### 3.2 目录

优先级（与 EPUB 一致思路）：
1. **章节识别**：对拼接后的全文跑内置章节正则（复用 V1.1 的 `buildToc`）——
   小说类 PDF 通常能识别出"第X章"，得到有意义的目录；
2. **回退页码**：识别不到章节时，用"第 N 页"作为目录条目（记录每页起始字符偏移）。

### 3.3 扫描版检测

若**总提取字符数 / 页数 < 20**（意为每页几乎没文字），判定为扫描版。

V6.0 当时是直接报错并建议 OCR；V6.1 改成**按页位图阅读**（不拒收）：
逐页 `page.render` 成位图存进 IDB，阅读页按页翻图，文字功能显式禁用。
整页缩放（底栏「－/适应/＋」与 Ctrl/Cmd+滚轮，最高 ×4）的尺寸由
[`src/core/scanView.ts`](../src/core/scanView.ts) 的纯函数**等比**算出 —— 位图不被
任何 CSS 钳制二次加工，任何倍数下都不会变形。详见
[V6.1-修复记录.md](./V6.1-修复记录.md)。

## 4. 边界与错误处理

| 情况 | 处理 |
| --- | --- |
| 加密 PDF（有密码） | 捕获 `PasswordException`，提示"该 PDF 有密码保护，请先解除后重试" |
| 文件损坏 | 捕获解析异常，提示可读原因 |
| 单页解析失败 | 跳过该页、记入 `warnings`，其余页照常导入 |
| 无文字（扫描版） | V6.1 起改为按页位图阅读（见 §3.3）；浏览器环境外（无 canvas）仍明确报错 + 建议 OCR |
| 超大 PDF（数百页） | 逐页处理并报告进度"解析页面 N/M"；解析完调用 `doc.destroy()` 释放内存 |
| 元信息 | 读取 PDF `Title` / `Author` 作为书名与作者兜底 |

## 5. 分期与规模

| 阶段 | 内容 | 规模 |
| --- | --- | --- |
| **V6.0-a 抽取管线** | pdf.ts（按需加载 + 逐页抽取 + 行段落组装）+ 类型/格式探测接入 + 扫描版与加密检测 | M |
| **V6.0-b 目录与元信息** | 章节识别优先、页码回退；Title/Author 提取 | S |
| **V6.0-c 测试与验证** | 行段落组装纯函数单测（合成 item）+ 真实 PDF 集成测试（仓内小样本）+ 浏览器实测 | M |

## 6. 验收标准

1. 导入一本**中文文字版 PDF**：正文完整、段落结构合理、无乱码；
2. 章节能被识别时目录可用；识别不到时可用"第 N 页"跳转；
3. 扫描版 PDF 给出明确的 OCR 建议而非空书（V6.1 起进一步改为可按页看图阅读）；
4. 加密 PDF 给出"请先解除密码"的明确提示；
5. **原有能力零回归**：TXT/EPUB/MD/HTML 导入与全部阅读功能不受影响；
6. **普通用户的加载体积不增加**（pdf.js 仅在打开 PDF 时加载）；
7. 打开 PDF 后，批注、搜索、朗读、进度续读均正常工作（因为它们基于字符偏移）。

## 7. 明确不做

| 项 | 原因 |
| --- | --- |
| **原始版式还原**（图文混排、表格、分栏） | 与"纯文本 + 字符偏移"模型冲突；要做等于重写整个阅读器为 canvas 渲染器 |
| **内嵌图片显示** | 同上（与 V5.0 对 EPUB 图片的取舍一致） |
| **扫描版 OCR** | OCR 引擎体积与复杂度远超阅读器本身，建议用户用专门工具处理后导入 |
| **PDF 表单/签章/注释读取** | 与阅读场景无关 |
| **加密 PDF 解密** | 无能力也无授权；明确提示用户先解除保护 |

## 8. 演进预留

- 若未来要做"版式还原模式"，应作为**独立的 PDF 阅读视图**（canvas + 文本层）与现有文本阅读器并存，
  而不是改造现有分页模型；
- pdf.js 的 `textContent` 也可用于**原页面高亮**：把批注的字符偏移反向映射到页面矩形，
  在 canvas 上叠加显示——作为"PDF 专属批注视图"的将来选项。
