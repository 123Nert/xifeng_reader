# V6.6 生词本方案

> 版本：V6.6 · 2026-09
> 前置：V6.4 划词翻译、V6.5 译文浮卡自动收起（均已交付）
> 定位：把"查一下就丢"的翻译，升级成"能攒下来、能回头翻"的生词本。

## 1. 对标调研

| 软件 | 生词本形态 | 值得借鉴 | 不跟进 |
| --- | --- | --- | --- |
| KOReader `vocabbuilder` 插件 | 查词弹窗里一键「加入生词本」，生词带书名/时间/次数，Tools → Vocabulary builder 集中管理，复习时"记住/没记住"两键 | **收藏即一键**（不打断阅读）、**记录出处**（哪本书哪个位置）、集中管理面板 | SQLite 服务化存储、间隔重复调度（依赖词典面板，本产品没有词典） |
| Kindle | 阅读中查词自动进 Vocabulary Builder，按书分组展示 | **零操作收集**（查过就留档）、按书过滤 | "生词本"曾是 Kindle 明确不跟进项——因为当时没有查词功能；V6.4 之后条件已具备，翻案 |
| 微信读书 | 生词本在"我的"页，查词卡片有「加入生词」按钮，支持导出到 Anki | 复习入口独立于阅读页、导出 Anki 的 CSV 思路 | 社交、打卡 |
| Anki / Readwise | 卡片正面是词，背面是释义 + 例句语境 | 导出格式对 Anki 友好（词、释义、例句三列） | 全套间隔重复系统 |

结论（克制原则）：

1. **本期只做"收 + 管 + 导出"**：收藏、列表、跳回出处、删除、导出 Markdown/CSV。
   间隔复习（SRS）依赖成熟的卡片系统，收益大但规模 L，列为 V6.7 候选，不塞进本期。
2. **收藏动作必须在翻译浮卡上**：V6.4 的闭环是"选中 → 浮卡 → 回到阅读"，
   生词收藏要长在这张卡上才不打断节奏（KOReader 也是查词弹窗内一键加入）。
3. **词 + 语境一起存**：V6.4 已经算了"所在整句"（`sentenceAround`），整句译文
   也常在浮卡里（`TranslationResult.context`）。只存单词的释义而没有语境，
   半个月后回看根本想不起当时读的是什么——这是和"收藏夹"拉开差距的地方。

## 2. 用户故事与验收标准

| # | 故事 | 验收 |
| --- | --- | --- |
| 1 | 读英文书查词，想把这个词攒下来 | 翻译浮卡出现「★ 生词」按钮；点击后按钮变「已收藏 ✓」，toast 确认；浮卡照常 V6.5 自动收起，不打断阅读 |
| 2 | 同一个词多次查到 | 第二次收藏提示「已在生词本」，并更新复习计数 + 语境为最近一次（KOReader 的 lookup count 同思路） |
| 3 | 回头翻生词本 | 阅读菜单新增「生词」页签：按时间倒序列出本人生词本里**当前这本书**的词 + 释义 + 整句语境；空态友好 |
| 4 | 想回到"当时读到这儿"的现场 | 生词条目点「回看」→ `jumpToOffset`，与目录/书签/搜索同一坐标系；跳转行为与 V4.0 批注跳转一致 |
| 5 | 攒了一堆想清理 | 每条可删除，删除即从浮卡收藏态同步消失（下次查这个词显示未收藏） |
| 6 | 想拿去 Anki / 复习 | 「导出生词」出 Markdown（人读）与 CSV（机器导，词/释义/语境三列，Anki 可直接吃） |
| 7 | 换浏览器/换机 | 生词进 IndexedDB 独立 store，全量备份（V2.0 exportBackup）自动带上 |
| 8 | 删除书 | 书没了生词也不留孤儿数据（`deleteBook` 级联删除） |

## 3. 技术方案

### 3.1 数据模型（DB v7）

```ts
// bookRepository.ts 新增 store（DB_VERSION 6 → 7）
vocab: {
  key: 'word'          // 全局小写归一化词 —— 同词跨书只一条（微信读书/Kindle 同款）
  value: VocabRecord
  indexes: { 'by-book': 'bookId' }
}

interface VocabRecord {
  word: string          // 归一化后的词（小写、去标点）
  bookId: string
  charIndex: number     // 收藏时选区起点 —— 跳回出处用
  excerpt: string       // 所在整句（语境），截断到 200 字
  gloss: string         // 主译文（浮卡的 result.text）
  alt?: string          // 另一义项（result.alt）
  context?: string      // 整句译文（result.context）
  lookups: number       // 收藏次数（重复收藏累加）
  createdAt: number
  lastLookupAt: number
}
```

设计取舍：

- **主键用词而不是 UUID**：Kindle Vocabulary Builder 同样"同词唯一"。
  好处是天然去重 + 浮卡能 O(1) 查"这个词收过没有"；坏处是跨书只保留
  最近一次语境——对"积攒阅读词汇量"的目标而言可接受，且 `bookId` 仍记录
  最近出处。by-book 索引用 `IDBKeyRange` 惰性计算某本书的词数，列表页
  一次 `getAllFromIndex` 拿全量（量级：个人生词本几百条，无压力）。
- **归一化规则**放纯函数 `normalizeWord`：trim → 小写 → 去首尾标点 →
  内部空白折叠。标点剥除限定 `[',.!?;:"“”()。！？；：]` 这类"选中时容易
  带上的壳"，不去词中间的连字符（well-known 是一个词）。
- **词长上限**：`isWordLookup` 已限定 1~3 词 / ≤24 字符才走"查词"路径，
  生词收藏只接受 `isWordLookup` 为真的选区，整段翻译不进生词本。

### 3.2 模块划分（core 纯逻辑 + 薄仓储）

```
src/core/vocabulary.ts        纯函数层（全可单测）：
  normalizeWord(text)                 归一化
  isVocabCandidate(text)              能否收藏（复用 translate.isWordLookup）
  buildVocabRecord({sel, result...})  从翻译结果组装记录（截断语境等）
  vocabToMarkdown(records, title)     导出 Markdown 文本
  vocabToCsv(records)                 导出 CSV（Anki 三列：词/释义/语境）
  mergeVocabOnRecollection(existing, next)  重复收藏的合并策略

src/core/bookRepository.ts    仓储层（新增于既有文件，同 bookmarks/highlights 风格）：
  addVocabRecord(record)     put（同词覆盖，lookups+1 由调用方合并好再传）
  getVocabRecord(word)       浮卡查"收过没有"
  listVocabByBook(bookId)    菜单页签列表（按 lastLookupAt 倒序）
  listVocabAll()             导出全文用
  deleteVocabRecord(word)
  deleteVocabByBook(bookId)  deleteBook 级联
  （backup: exportBackup/importBackup 增加 vocab 段）
```

### 3.3 交互改动

**翻译浮卡（Translator.tsx）**

- `tr-actions` 增加「★ 生词」按钮：只在 `isWordLookup(source)` 时出现
  （整段翻译没有"词"可攒，藏起来不添乱）。
- 新 prop：`vocabState: 'none' | 'saved' | 'added'`（none = 不是词或未收藏；
  saved = 打开卡时就已收藏；added = 本会话刚点过收藏）。
  按钮文案对应「★ 生词」/「已在生词本 ✓」/「已收藏 ✓」，`added/saved` 时禁用。
- V6.5 的"移开即收起"判定完全不动——收藏按钮在卡内，指针移向它的途中
  不会触发收起（`isPointerInsideCard` 已覆盖）。

**ReaderPage**

- `startTranslate` 成功后顺手 `getVocabRecord(normalizeWord(sel.text))`，
  把"是否已收藏"并进浮卡状态（不阻塞主翻译，Promise.all 即可）。
- 新增 `collectWord` 回调：组装记录（`sentenceAround` 已有，语境现成）、
  `mergeVocabOnRecollection` 处理重复、`addVocabRecord` 写库、
  toast「已加入生词本」/「已在生词本，已更新语境」、置浮卡 `added` 态。
- 生词保存失败（IDB 异常）只 toast 报错，绝不让阅读中断。

**ReaderMenu（阅读菜单）**

- `MenuTab` 增加 `'vocab'`，页签列表在「笔记」后插入「生词」。
- 页签内容：工具行（N 个 · 导出 Markdown · 导出 CSV）+ 列表。
  条目布局：词（大）+ 释义（小，超出两行截断）+ 语境整句（再小一档，
  折行显示）+「回看」「✕」操作。按 lastLookupAt 倒序。
- 回看 = 既有 `onJumpOffset(charIndex)`，与书签完全同一通路；
  PDF 原版视图下同样经由 `jumpToOffset` 先落文字坐标系再翻页（既有逻辑复用）。
- 「生词」页签对扫描版（无可跳转坐标系的书）隐藏——与搜索页签同款限制。

**书库 LibraryPage**：本期不动。全局生词本（跨书聚合面板）等产品验证
"按书过滤够不够用"后再立项，避免一次铺太多。

### 3.4 需要小心的点

1. **浮卡打开瞬间的"已收藏"查询别挡渲染**：翻译本身是异步的，
   `getVocabRecord` 也异步，用 `Promise.all` 并行；浮卡先出"翻译中"，
   收藏态回来再补——用户点收藏按钮至少在译文到达之后，不会出现
   "按钮还没就绪"的窗口。
2. **重复收藏的语义**：不新增记录，`lookups + 1`、语境/释义/出处
   更新为最近一次、`createdAt` 保留首次。这是 KOReader lookup count
   的简化版（它还区分 re-mastery，本期不做掌握度）。
3. **CSV 转义**：语境含逗号/引号/换行，字段一律 `"` 包裹 + 内部 `"` 加倍
   + 换行替换为空格，Excel/Anki 双兼容。BOM 头（`\uFEFF`）让 Excel
   正确认 UTF-8 中文。
4. **归一化后空串**（选中的全是标点）：`isVocabCandidate` 直接拒，
   不写库。防御式，正常到不了这里。
5. **备份兼容**：老备份无 `vocab` 段照常导入（`?? []`），新备份带
   `vocab` 进旧版本 App 也不炸（未知字段被忽略——importBackup 白名单式写 store）。
